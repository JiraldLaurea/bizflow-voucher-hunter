# Development Log — 2026-08-07

## Security
- Fixed four critical vulnerabilities found in a security audit: OTP sign-in could be brute-forced, rate limiting could be bypassed by any caller, admin login had no attempt limit, and developer-only tools (free loyalty point grants, forced roulette outcomes, a super-admin login) could be exposed on staging or preview deployments.
- Closed supporting gaps: prize draws are now unpredictable, voucher and loyalty codes are no longer guessable, voucher resend requires sign-in, disabling or demoting an account takes effect immediately, and baseline security headers were added.
- Added a reusable security audit command, two new test suites, and documented trust boundaries and accepted risks in `docs/SECURITY.md`.

## Performance
- Dashboard reads session and shared data once per request instead of repeatedly, cutting database round trips per page.
- Restored page prefetching on the dashboard, so sidebar navigation no longer waits on a cold server render.
- Each dashboard page now shows a loading placeholder matching its own layout instead of a generic one.

## Product and UI
- Retired the "BizFlow" name across the app, docs, and SMS sender ID; the product is now Voucher Hunt throughout, with the wordmark in a new typeface.
- Dashboard logo now links back to Overview; staff accounts see their assigned business named in the account menu.
- Pool availability now lists readable dates with weekday and month names instead of raw ISO dates.
- Mobile roulette uses a single button through the spin-and-confirm flow instead of two controls swapping places.
- Mobile More tab: removed duplicate loyalty conversion and voucher screens that already exist elsewhere in the app; added a link to the customer landing page.

## Cleanup
- Removed the per-venue staff PIN. It was collected and stored on every business but never actually checked, implying a second factor that did not exist. Staff access runs through admin accounts.
